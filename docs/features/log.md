## 2026-10-06

- **Updated**: [LLM Settings API](/llm-settings-api.md) and [Vision Provider Abstraction](/vision-provider-abstraction.md) — ticket 3.3 review fixes: OpenAI now wraps the item array under an object root (`{ items: [...] }`) so Structured Outputs accepts it; changing `provider` via `PUT` without supplying `apiKey`/`model` clears the previous provider's stored ciphertext/model so its secret is never sent to the new backend; `unknown_provider` is documented as defensive-only.
- **Added**: [LLM Settings API](/llm-settings-api.md) — ticket 3.3: `GET`/`PUT /settings/llm` and `POST /settings/llm/test` (always `200`, `{ ok, code }`) backed by a singleton `llm_settings` row; the API key is write-only, AES-256-GCM encrypted with a key derived from `LLM_SETTINGS_SECRET`/`SESSION_SECRET`, never returned or logged; provider/model/key precedence is stored-row (active provider) → per-provider env (`GEMINI_API_KEY`/`OPENAI_API_KEY`) → none; the upload gate is now `keyPresent`/`importEnabled`.
- **Added**: [Vision Provider Abstraction](/vision-provider-abstraction.md) — ticket 3.3: one `VisionProvider` interface with Gemini (default `gemini-3.8-flash`) and OpenAI (`gpt-4o-mini`) implementations behind `VisionProviderRegistry` and the `VisionService` facade, a shared prompt/item schema adapted per API, `VisionHttpClient` as the test seam, and a safe error-code taxonomy.
- **Updated**: [Import Photo Upload API](/import-upload-api.md) — ticket 3.3: the LLM gate now reads `LlmSettingsService.isConfigured()` (stored encrypted key for the active provider or the per-provider env key), not the removed env-only `LlmConfigService`.
- **Added**: [Import Photo Upload API](/import-upload-api.md) — ticket 3.2: `POST /import/upload` multipart endpoint that accepts up to 10 JPEG/PNG/WebP photos (15 MB each), with an optional index-aligned `declaredCounts` field, validates and stores them in the ephemeral `IMPORT_PHOTOS_DIR` (no static serving), creates one `queued` `import_jobs` row per photo (new nullable `photo_ref`), enqueues one BullMQ `photo` job per photo (`{ photoRef, declaredCount }`), returns `202` with the job ids immediately, and refuses with `503` before storing/enqueuing when no LLM provider key is configured.
- **Added**: [User CLI](/user-cli.md) — ticket 2.7: `npm run user:create` / `npm run user:passwd` operator commands that boot the Nest application context with `ts-node`, reuse `UsersService.createUser`/new `setPassword` (shared `prepareUser` hashing, normalization, and max-length bounds), prompt for the password without echoing it on a TTY (confirm-twice) and read a single stdin line when non-TTY, reject any password passed via argv, exit non-zero with a readable stderr message on failure, and need no email/SMTP infrastructure.
- **Updated**: [Web Auth UI](/web-auth-ui.md) — ticket 2.6: authenticated navigation shell (catalog/platforms/import/settings), optimistic `middleware.ts` cookie check, request-cached `requireUser()` guard in the shell and every protected route, and the session-expiry-on-navigation behavior.
- **Added**: [Web Auth UI](/web-auth-ui.md) — the Next.js (`apps/web`) login/setup wiring for ticket 2.5: server-side route protection (`/setup` ↔ `/login` setup-state redirects, `(app)` layout session guard), the same-origin `/api` rewrite that keeps the `gameshelf_session` httpOnly cookie on the web origin, SSR cookie forwarding in `lib/api.ts`, the cookie-only/no-token guarantee, status-to-message error handling (notably `400` → input-validation message vs `401` non-leaking credentials vs generic network fallback), and a six-criterion manual acceptance script with the proxy smoke commands and expected statuses.

## 2026-10-05

- **Updated**: [Auth API](/auth-api.md) and [Auth Foundation](/auth-foundation.md) — recorded that public self-registration is deliberately disabled (only the one-time `POST /setup` and the future operator CLI create users) and corrected the stale "signup" wording; added an e2e regression spec (`apps/api/test/e2e/no-registration.e2e-spec.ts`) asserting that `POST /auth/register` and similar paths return `404` and create no user.
- **Updated**: [First-run Setup](/first-run-setup.md) and [Auth API](/auth-api.md) — the atomic first-user insert is now retried up to `MAX_SETUP_ATTEMPTS` times with a `hasAnyUser()` re-check after each failure, so a losing concurrent `POST /setup` is guaranteed `409` even when the winner's row is not yet visible; a genuine error with no user created is still rethrown. Corrected the stale "(web integration, ticket 2.3)" reference in the Auth API out-of-scope list to ticket 2.5, and added a `forbidNonWhitelisted` unknown-field e2e case.
- **Added**: [First-run Setup](/first-run-setup.md) — `GET /setup/status` (is the `users` table empty?) and `POST /setup` (create the very first account), both `@Public()`; a single atomic `INSERT … SELECT … WHERE NOT EXISTS` plus a post-failure re-check guarantees exactly one winner under concurrency (losers get `409 Setup has already been completed`); shares `UsersService.prepareUser()` with the CLI creation path and logs one info line on success.
- **Added**: [Auth API](/auth-api.md) — `POST /auth/login` (sets the `gameshelf_session` httpOnly/Lax cookie), `POST /auth/logout` (server-side revoke + clear), `GET /auth/me`, a single global `SessionGuard` with `@Public()` opt-outs, the `SESSION_COOKIE_SECURE` config knob, and one generic 401 for bad credentials with a dummy-hash timing equalizer.
- **Added**: [Auth Foundation](/auth-foundation.md) — Argon2id password hashing (`PasswordService`), a MySQL-backed server-side session store whose `sessions.id` holds the HMAC-SHA256 digest of the cookie token (`SessionsService`), finite sliding expiry validated from `SESSION_TTL_MINUTES` (no "never"), an hourly expired-row sweep (`SessionCleanupService`), and env-only configuration (`SESSION_SECRET`). No JWT.
- **Added**: [Import Jobs API](/import-jobs-api.md) — `GET/PATCH /import-jobs`: persisted import runs (status + recognized/imported/unrecognized/declared counts, newest first), per-job flagged-item review (`raw_title` trace, non-dismissed review queue vs full trace), idempotent dismissal of needs-attention/failed jobs and flagged items (sticky, 409 matrix), the pipeline surface (`createJob`/`markProcessing`/`markCompleted`/`markFailed`/`addUnrecognizedItem`) with server-side `done` vs `needs_attention` per spec §4.2.4, and the indefinite retention policy (no TTL, no DELETE).
- **Added**: [Platforms API](/platforms-api.md) — platform CRUD (`GET`/`POST`/`PATCH`/`DELETE` `/platforms`) with per-platform game counts (single `groupBy` aggregate, no N+1), 409 on duplicate name and on delete while games reference the platform, stable slugs across renames, and the canonical IGDB platform list loaded as a seed data-migration generated by the `db:platforms:fetch` script (initial seed pending IGDB credentials).
- **Added**: [Catalog API](/catalog-api.md) — `GET /games` contract: AND-combined filters, case-insensitive partial title search (`q`), deterministic sorting with `id` tiebreaker, filtered pagination totals, available filter values, and filter-column indexes.
