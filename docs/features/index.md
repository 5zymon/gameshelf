# Features

- [Auth Foundation](auth-foundation.md) - Argon2id password hashing, server-side sessions (HMAC-stored ids, finite sliding TTL), and env-only auth config.
- [Auth API](auth-api.md) - `POST /auth/login`, `POST /auth/logout`, `GET /auth/me`, the `gameshelf_session` httpOnly cookie, and the global `SessionGuard` (with `@Public()` opt-outs).
- [First-run Setup](first-run-setup.md) - one-time `GET /setup/status` / `POST /setup` bootstrap that creates the first account and is permanently disabled once one exists.
- [Catalog API](catalog-api.md) - `GET /games`: paginated, filterable, searchable, sortable game listing with available filter values.
- [Import Jobs API](import-jobs-api.md) - persisted import runs (status, counts, flagged items), dismissal, and the indefinite retention policy.
- [Import Photo Upload API](import-upload-api.md) - `POST /import/upload`: multi-photo upload, optional per-photo declared counts, ephemeral storage, and background queuing.
- [Photo Import Pipeline](photo-import-pipeline.md) - the in-process MySQL-backed worker's per-photo pipeline: one vision call, IGDB validation, per-batch MySQL transactions, retry-only-unresolved, and photo deletion after completion.
- [ADR-005 — MySQL Photo-import Queue](adr-005-mysql-photo-import-queue.md) - the `import_jobs` table is the single photo-import queue (claim with `FOR UPDATE SKIP LOCKED`, lease, retry, stall recovery, durable pause), superseding ADR-002.
- [ADR-006 — UUIDv7 primary keys](adr-006-uuidv7-primary-keys.md) - every non-singleton primary and foreign key is an app-generated UUIDv7 `CHAR(36)`; `@IsUUID('7')` validation (400 malformed, 404 unknown), creation-order `ORDER BY id`, raw-SQL ids from `common/uuid-v7.ts`, and one wiping migration.
- [Queue Pause on Configuration Error](queue-pause-on-config-error.md) - a rejected/absent LLM, IGDB, or MobyGames credential fails the current photo, durably pauses the photo-import queue, surfaces the pause on batch progress, and resumes explicitly or when the LLM key is saved.
- [Anti-hallucination Validation](anti-hallucination-validation.md) - no `Game` row without external confirmation: the ordered IGDB → MobyGames → unrecognized chain, transient short-circuit, unrecognized trace, and MANUAL-only bypass.
- [MobyGames Fallback](mobygames-fallback.md) - a rate-limited MobyGames v2 client (1 req/s, 720 req/h that waits) consulted only for titles IGDB missed, mapped onto the shared candidate shape with MobyGames provenance, degrading to IGDB-only when no key is configured.
- [IGDB Client & Rate Limiter](igdb-client.md) - one IGDB client: Twitch client-credentials auth, cached/refreshable token, a central 4 req/s / 8-concurrent limiter, internal 429 backoff, two-phase IGDB batching (batched id search + batched hydration, ≤10 sub-queries and ≤500 ids per request), and an unauthenticated `GET /health/igdb` probe.
- [Game Metadata Enrichment](game-metadata-enrichment.md) - one reusable candidate→`Game` mapping (title/platform/year/publisher/genre/playerCount, vision-only edition) plus a minimal local cover cache served same-origin at `/api/covers/<file>`, with honest source/enrichedAt and never-queried raw archival.
- [Game Re-enrichment](game-reenrichment.md) - `POST /games/:id/enrich` searches the catalog through the IGDB-first search seam (ranked list, best first, up to 10; MobyGames only when IGDB returns no candidates) against a game's current (corrected) title, and applies any picked candidate's fresh metadata in place without duplicating the row or overwriting title/platform/edition or hand-edited (provenance-tracked) fields.
- [Manual Add with DB Search and Copy Count](manual-add-and-copy-count.md) - `GET /games/search` (debounce-protected external search) plus `POST /games` with an optional picked candidate or typed-only data; one shared identity rule (reused by the import commit) turns an existing identity into a `409` carrying the game, `POST /games/:id/copies` increments the new `copyCount`, and imports link duplicates without incrementing.
- [Local Cover Cache](local-cover-cache.md) - downloaded game covers stored in `COVERS_DIR`, locally generated WebP catalog thumbnails, same-origin serving (`/covers/:file`, `/covers/thumbs/:file`, `/covers/preview`), a `@Interval` background retry (ADR-005: no second queue), ref-counted deletion/replacement, and the `covers:redownload` repair command.
- [Photo Lifecycle & Retention](photo-lifecycle.md) - ephemeral photo lifecycle: kept while queued/retryable, deleted on completion, swept when orphaned or past the failed-retry window.
- [Vision Provider Abstraction](vision-provider-abstraction.md) - one `VisionProvider` interface with a single Custom (OpenAI-compatible) backend behind a registry and `VisionService` seam, and a list-based (never count-based) recognition contract.
- [LLM Settings API](llm-settings-api.md) - `GET`/`PUT /settings/llm` and `POST /settings/llm/test`: runtime provider/model/key config, encrypted-at-rest key, and the import gate.
- [LLM Settings UI](llm-settings-ui.md) - the /settings screen: provider/key config, a saved-config connection test, game-database status, and platform refresh.
- [Platforms API](platforms-api.md) - platform CRUD with game counts, rename-preserving aliases, merge/confirm, delete-or-hide rules, import-created platforms, and the canonical IGDB platform list synced locally by `npm run platforms:sync`.
- [Platforms UI](platforms-ui.md) - the /platforms management view: game-count list, add/rename/delete/hide, merge-with-alias, the import-created review block, and canonical-vs-manual badges.
- [Collection Statistics](stats.md) - the /stats page and `GET /stats`: the number of games (titles) and physical copies, games per platform and the count of games waiting for platform recognition, with an import prompt for an empty collection.
- [Catalog CSV Export](catalog-export.md) - the /export page and `GET /export/csv`: the whole catalog as one RFC 4180 CSV file (`gameshelf-YYYY-MM-DD.csv`, 12 English columns, UTF-8 without BOM, no formula-injection guard yet), header-only when the collection is empty.
- [Web Auth UI](web-auth-ui.md) - browser login/setup flows, the authenticated navigation shell (catalog/platforms/import/settings), layered server-side route protection, the same-origin `/api` rewrite, and the cookie-only (no token) auth guarantee, with a manual acceptance script.
- [Web API Client](web-api-client.md) - one typed frontend API client plus shared `@gameshelf/contracts` wire types, centralised base URL/credentials, query builders, and a single typed `ApiError`.
- [Catalog Grid](catalog-grid.md) - the server-paginated cover-art grid at `/` with title/platform tiles, a gradient initial-tile placeholder for missing covers, same-origin thumbnails, lazy loading, and an empty state pointing at manual add and photo import.
- [Catalog Filters & Search](catalog-filters.md) - search, multi-select platform chips (draggable one-line scroller with momentum, wheel and edge fades), title/year sort and a collapsible advanced filter panel on /, URL-synced.
- [Game Detail View with Edit, Delete & Re-enrich](game-detail.md) - the `/games/[id]` route: record view, inline PATCH edit, confirmed DELETE, re-enrich with reported outcome, provenance/enrichment state, and grid tiles linked to detail.
- [Game Image Gallery & High-Resolution Covers](game-image-gallery.md) - IGDB t_1080p covers and a cached screenshots/artworks gallery with a lightbox on the detail page.
- [Game Summary, Rating & YouTube Videos](game-summary-rating-videos.md) - IGDB description (summary), 0–100 user rating (list + detail), and YouTube videos: a `GameVideo` table, a click-to-play detail player, and a scoped CSP `frame-src` exception.
- [Catalog Loading, Error & Responsive States](catalog-states.md) - route-level loading skeletons for `/` and `/games/[id]`, error boundaries with a working retry, slow-cover handling with descriptive alt text, dialog/disclosure focus management, and mobile polish/de-templating for the catalog screens.
- [Single-Origin Frontend & API with Strict CSP](single-origin-frontend-api.md) - one origin via the `/api` rewrite, first-party session cookie, nonce-based `'self'`-only CSP, and build-time self-hosted fonts.
- [User CLI](user-cli.md) - operator-run `user:create`/`user:passwd` commands that reuse `UsersService`, prompt interactively (or accept `--email`/`--password`) without echoing the password, and need no email infrastructure.
- [Dev Data Clear](dev-data-clear.md) - the development-only `db:clear-dev` command: one transaction that deletes all games, import data and platforms while keeping accounts, sessions and LLM settings, behind a `NODE_ENV=development` gate and a confirmation prompt.
- [Dev Seed](dev-seed.md) - the development-only `db:seed` command: idempotently creates the `qa@gameshelf.local` QA account, three IGDB-named platforms and six MANUAL sample games behind a `NODE_ENV=development` gate.
- [Manual Add Form](manual-add-form.md) - the `/games/new` typed-only form: platform select with inline quick-create, optional metadata, save-and-add-another, field-level errors, and the existing-identity copy prompt; a compact variant is reused inline by the import review.
- [Photo Import Upload UI](photo-import-upload-ui.md) - the `/import` screen: drag-and-drop, browse, or paste multi-photo picker, local thumbnails, optional per-photo counts, client-side 20 MB/50-photo validation, in-browser HEIC→JPEG conversion, an LLM-readiness gate with a manual-entry fallback, and upload progress navigating to `/import/progress/[batchId]`.
- [Import Progress UI](import-progress-ui.md) - the `/import/progress/[batchId]` view: aggregate X-of-Y progress, per-photo states in one Photos list (inline flagged-title review with catalog search/pick and a compact add form, retry, dismiss), live polling (2 s running / 15 s paused heartbeat) that stops when the batch completes, and a queue-paused banner with resume.
- [Internationalization (EN default, PL)](i18n.md) - English-default UI with a Polish option: the per-user language persisted server-side (`users.language`), the `NEXT_LOCALE` cookie bridge, per-request next-intl resolution with an `en` fallback, typed PL/EN message catalogs with a parity test, locale-aware date/size formatting, the `/settings` Preferences switcher, and the `no-hardcoded-strings` lint guard.
- [Theme (light/dark/system)](theme.md) - the per-user UI theme persisted server-side (`users.theme`, default `system`), the `NEXT_THEME` cookie bridge, class-based Tailwind v4 dark mode over the Nocturne palette (Sora/Manrope, warm light + premium dark) with a no-flash `beforeInteractive` bootstrap script, live OS tracking for `system`, and the theme select in the same `/settings` Preferences view as the language.
- [Database Connection & Boot Readiness](database-connection.md) - the API's runtime MySQL connection through the Prisma mariadb driver adapter: `caching_sha2_password` with `allowPublicKeyRetrieval`, and the boot gate that waits for a real `SELECT 1` before building the pool (which never recovers from a failed first connection).
- [Operator Runbook](references/runbook.md) - thin runbook mapping operator situations (setup, accounts, backup/restore, health checks, credentials) to the sections of the reference guides that hold the commands.
- [Installation & First Run](references/installation.md) - scope, prerequisites, one-command (`npm run setup`) and manual setup, running on `WEB_PORT`/`API_PORT`, LAN access, and how accounts are provisioned (no public sign-up).
- [Configuration & External Services](references/configuration.md) - LLM (OpenAI-compatible vision), IGDB and MobyGames credentials and the full root `.env` variable table.
- [Database, Backups & Operational Checks](references/operations.md) - MySQL 8.4/utf8mb4 setup, the `gameshelf-mysql-data` volume, Prisma migrations, `mysqldump` backup and restore, health checks, and the Redis-era upgrade.
- [Development Guide](references/development.md) - workspaces, root npm scripts, Task shortcuts, git hooks, the two-tier test suite, CI gates, and the repository layout.
