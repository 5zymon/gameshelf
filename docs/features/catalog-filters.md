# Overview

The [Catalog Grid](catalog-grid.md) at `/` is server-rendered and `force-dynamic`. Ticket 5.3 added a filter/search bar above the grid that narrows the catalog through the existing [`GET /games` contract](catalog-api.md). Multi-select platform chips later changed `GET /games` and the contract to accept a repeated `platformId` (OR-combined) — see [Catalog API](catalog-api.md).

The URL is the single source of truth: the server component awaits `searchParams`, `parseCatalogFilters` validates them into a typed filter object, and that object is both sent to `getGames` and passed as the committed values to the client bar. The bar is a `'use client'` component receiving those committed values plus the `games.filters` options as props; every change calls `router.push('/?…')`, which triggers an RSC re-render and a fresh server fetch. There is no `useSearchParams`, no client-side data-fetching library, and no new dependency. Pagination stays server-rendered `<Link>`s and preserves the filters automatically.

# Parameters

Every filter is AND-combined server-side; the selected platforms are OR-combined with each other. Both the server parser and the client builder only ever emit the keys below, so an unknown or invalid param is dropped (`''`, non-numeric, a malformed `platformId`, out-of-range, or >255 characters) rather than sent — this is what keeps the endpoint from answering `400`.

| Param                | Control                                                               | Bounds / semantics                                                                                                                                                                                                                                                         |
| -------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `q`                  | Search titles (debounced, leading icon, `searchPlaceholder`)          | Case-insensitive partial title match, ≤255 ch                                                                                                                                                                                                                              |
| `platformId`         | Platform chips (multi-select toggles, from `games.filters.platforms`) | Repeated `platformId=<uuid>` (ascending, de-duplicated, ≤100), each a UUIDv7; a game on any selected platform matches; an unknown but well-formed id matches nothing, never `400`; a malformed value is dropped on parse; a single legacy `?platformId=<uuid>` still works |
| `edition`            | Edition select (options from the API)                                 | Exact match, ≤255 ch                                                                                                                                                                                                                                                       |
| `year`               | Year text field                                                       | Integer 1000–2100                                                                                                                                                                                                                                                          |
| `yearFrom`           | Year from text field (More filters)                                   | Integer 1000–2100; releaseYear ≥ value, inclusive; no chip                                                                                                                                                                                                                 |
| `yearTo`             | Year to text field (More filters)                                     | Integer 1000–2100; releaseYear ≤ value, inclusive; no chip                                                                                                                                                                                                                 |
| `noYear`             | No release year checkbox (More filters)                               | Only the literal `true` is kept (`false`, `1`, empty are dropped); only games without a release year; no chip                                                                                                                                                              |
| `platformUnverified` | Platform to be recognized checkbox (More filters)                     | Only the literal `true` is kept; only games whose platform is unverified; no chip                                                                                                                                                                                          |
| `publisher`          | Publisher text field                                                  | Exact match, ≤255 ch                                                                                                                                                                                                                                                       |
| `genre`              | Genre text field                                                      | Exact match, ≤255 ch                                                                                                                                                                                                                                                       |
| `playerCount`        | Players text field                                                    | Integer 1–100                                                                                                                                                                                                                                                              |
| `sort`               | Sort select (`sort.titleAsc`/…)                                       | `title` \| `year`, default `title`; omitted from the URL at the default                                                                                                                                                                                                    |
| `order`              | Sort select (`sort.titleAsc`/…)                                       | `asc` \| `desc`, default `asc`; omitted from the URL at the default                                                                                                                                                                                                        |

`platformId`, `edition`, `year`, `yearFrom`, `yearTo`, `noYear`, `platformUnverified`, `publisher`, `genre`, `playerCount` and `q` are exactly the query layer's filter keys. `sort`/`order` are surfaced by the sort select and validated against a `title`/`year` + `asc`/`desc` whitelist: any other value — including the API-supported `platform`/`createdAt` fields — is dropped on parse, along with a lone `order`. The default pair (`title` + `asc`) is never written to the URL, so the default-bar href stays `/`.

The four T-05 filters are the targets of the links on [Collection Statistics](stats.md): arriving with any of them in the URL opens the advanced panel on its own, shows the filled controls and counts them in the toggle badge, and **Clear all** clears them. They are AND-combined with every other filter, so contradictory values (for example `noYear` with a year) show the no-results state. They have **no chips** in the active-filter row.

The **Search titles** field renders a decorative leading magnifier icon (`aria-hidden`, `pointer-events-none`, `text-faint`) and pads the input so text never overlaps it. Its accessible name comes from a visually hidden `<label>` (`searchTitles`); the visible placeholder is `searchPlaceholder`.

# Components

- `apps/web/src/lib/catalog-filters.ts` — server/client-shared pure helpers: `CatalogFilterValues`, `CatalogSearchParams`, `FILTER_KEYS`, `MAX_PLATFORM_IDS`, `parseCatalogFilters` (whitelist + bounds, including the `sort`/`order` pair and the de-duplicated ascending `platformId` list), `hasActiveFilters` (ignores sort), `canonicalPlatformIds`, `togglePlatformId`, `removePlatformId`, `SORT_OPTIONS`, `DEFAULT_SORT`, `sortOptionOf`, `sortOverrides`, and `catalogHref` (builds `/?…` from valid values — repeated `platformId` in canonical ascending order — always dropping `page`).
- `apps/web/src/lib/scroll-edges.ts` — `scrollEdges` (pure scroll-metrics → `{ start, end }` fade state, 1 px tolerance).
- `apps/web/src/lib/drag-scroll.ts` — pure drag/wheel helpers: `maxScroll`, `clampScroll`, `isDragGesture` (5 px threshold), `releaseVelocity` (100 ms window, 50 ms idle, ±4 px/ms clamp), `momentumStep` (exact exponential decay, 0.95 per 60 Hz frame, 32 ms dt cap), `wheelScrollDelta`, `consumesWheel`, `wheelGestureOwner` (250 ms latch), and the tuning constants.
- `apps/web/src/lib/use-drag-scroll.ts` — the `useDragScroll` hook: mouse drag-to-pan (pointer capture after the threshold, post-drag click suppression), the release glide (`requestAnimationFrame`, cancelled by a new press, a wheel event, a keyboard focus reveal or unmount; none under reduced motion), and the non-passive vertical-wheel listener with the window-capture gesture latch.
- `apps/web/src/components/catalog-filter-bar.tsx` — the `'use client'` `CatalogFilterBar`: search field, multi-select platform chips in a draggable one-line scroller with scroll-position edge fades, sort select, the collapsible advanced panel, 300 ms debounce, active-filter chips, and clear-all. Receives committed values and API options as props.
- `apps/web/src/app/(app)/(catalog)/page.tsx` — parses filters, sends them to `getGames` with a `title`/`asc` default sort, renders the bar between the header and the grid, chooses `EmptyCatalog` vs `NoResults`, and renders the filtered range line.

# Out of scope

- Persisting the advanced panel's open/closed state in the URL (it opens automatically when an advanced filter is active).
- `platform` and `createdAt` sort options — API-supported but not surfaced in UI; hand-edited URLs fall back to the default.
- Facet lists for the extended fields (year/publisher/genre/playerCount) — the contract exposes `platforms`/`editions` only, so those fields are free-text exact-match inputs.
- Facet endpoints (the only contract change is the repeated `platformId`).
- A visible scrollbar (deliberately hidden) or arrow buttons.
- A JS drag for touch/pen (native panning).
- Game detail links (ticket 5.4) and i18n (7.2).

# Manual acceptance

1. Open `/?q=hollow`: the grid narrows to titles containing "hollow"; the header reads "Showing 1–N of M matching games"; the URL is shareable and a reload reproduces the result.
2. Type in **Search titles** and pause: exactly one navigation happens per pause (≤1 push per 300 ms quiet period), and no request is fired per keystroke.
3. **Platform chips**: the row shows **All** plus one chip per API platform in name order; clicking a chip toggles it (`aria-pressed`, accent-filled) and adds/removes its `platformId` — with two chips selected the grid shows the union and the URL is `?platformId=<a>&platformId=<b>` in ascending order; **All** is pressed only when nothing is selected and clicking it clears the selection; the old single form `/?platformId=01926f3b-1c2d-7e3f-8a4b-5c6d7e8f9a0b` still works; spot-check the chips against `GET /games` `filters.platforms`.
4. Combine a search with a platform, year, publisher, genre, and player count: the result is the AND of all of them.
5. Chip row: every active filter has a chip; clicking a chip's `×` removes just that filter; **Clear all** clears every filter but keeps the sort.
6. Browser **Back** after a filter change restores the previous filtered grid; **Forward** re-applies it.
7. Filter to a term with no matches: **No games match these filters** appears with the bar still visible; **Clear all filters** resets the grid while keeping the sort.
8. With >24 matching games, **Next** preserves the filters and the sort and adds `page=2`; changing a filter or the sort resets to page 1.
9. With an empty library (no filters), the existing "Nothing on the shelf yet" entry state shows and no filter bar is rendered.
10. The URL never contains an invalid/out-of-range value after using the controls (e.g. year `99999` or a blank text field), and the API never returns `400` from the bar.
11. **Sort**: with no `sort` param the grid is Title A–Z; choosing **Title (Z-A)** writes `sort=title&order=desc`; **Release year (newest)** / **Release year (oldest)** order by year with unknown years last; the sort survives **Next**/**Prev**, a filter change, **Clear all** and the no-results **Clear all filters**.
12. **Advanced panel**: the **Advanced filters** toggle opens/closes the inline panel (`aria-expanded`/`aria-controls="catalog-advanced"`); opening `/?genre=RPG` starts it open with a count badge; pressing Tab from the toggle enters the panel fields.
13. **Chip scroller**: with more platforms than fit, the chips stay on one line; at rest only the right fade shows; scrolling right shows both; at the far right only the left fade shows; Tab through the chips scrolls each into view with its focus outline unclipped; at 375 px and 1280 px the page has no horizontal scroll; both themes show a seamless fade. Dragging from anywhere on the strip — including on a chip — pans it 1:1 without toggling the chip; a fast release glides and slows down, a slow one stops dead; the glide stops at either end and on any new press; the vertical wheel scrolls the strip sideways until it reaches an end, then scrolls the page; a page scroll that passes over the strip is not hijacked; touch keeps native scrolling.
14. **Unknown platform ids**: `/?platformId=01926f3a-8c4e-7b21-9d3f-2a6b8e4c1f70` (a well-formed v7 that matches nothing) shows no pressed strip chip, **All** is not pressed, the grid shows **No games match these filters**, and the active row shows a removable `Platform: Unknown platform` chip; with a known id mixed in (`?platformId=01926f3c-2d3e-7f40-9b5c-6d7e8f9a0b1c&platformId=01926f3a-8c4e-7b21-9d3f-2a6b8e4c1f70&platformId=01926f3b-1c2d-7e3f-8a4b-5c6d7e8f9a0b`) the known chip is pressed, the results come from the known ids only, and each unknown id has its own removable chip. A malformed value (`?platformId=999999`, `abc`, or a v4 UUID) is dropped by the parser and never sent.
15. **Stats links (T-05)**: open `/?yearFrom=1990&yearTo=1999`, `/?noYear=true` and `/?platformUnverified=true`: the advanced panel starts open with the matching controls filled and the badge counting them, no chip is shown for them, the header total matches the number on `/stats`, and **Clear all** resets the grid and the controls. `/?noYear=1` ignores the value and shows the unfiltered catalog.
